### @gregisenberg · 2026-11-04 05:45

如今经营一家公司感觉有点反乌托邦

我的团队有 50 多人、分布在 12 个国家，但我跟我的 agent 说话比跟人类同事还多

- 给 grokbot 发语音备忘
- 用 mattpocock/skills 的 /grill-me，让 agent 在动手构建前先把这个想法盘问一遍
- spec 通过 linear mcp 直接落进 linear
- exa + firecrawl 的 agent 读遍每个竞品的网站、定价页和更新日志
- 用 https://t.co/a5ARFnvSnA（ideabrowser.com）找点子和趋势
- apify 抓取 g2、reddit 和 app store 的评论
- 提示词："找出出现最多的 10 条抱怨，并引用用户原话"
- context7，让 agent 在碰任何 api 之前先读最新文档

设计

- claude code + paper mcp
- 每个页面先出 4 个版本，再写一行代码
- 从其中 2 个里挑部分，让它合并。先发散再收敛
- 用 anthropic/skills 里的 frontend-design skill + 我们自己的设计系统 skill
- 看到喜欢的 ui 就用 cleanshot 截图，直接丢进去说"做成这种感觉"

构建

- 用 pingdotgg/t3code 作为所有 agent 的控制台，手机上也能用
- stablyai/orca 并行跑一队 agent，每个都在自己的 git worktree 里
- graphify 把整个代码库映射成知识图谱，让 agent 按图导航而不是瞎猜
- headroom 在工具输出喂给模型之前先压缩，让 token 多撑 20-95%
- lsp 插件让 agent 像 ide 一样看到类型和报错
- 安全指引 hook 在高风险修改落地前就标记出来
- 数据库用 supabase mcp，计费用 stripe
- github mcp 开 pr，vercel 起一个预览环境
- 循环任务通宵跑，我边喝咖啡边看昨晚上线了什么

用户测试

- 用 lightpanda 做无头浏览器，比 chromium 轻得多，能同时跑几百个
- agent 像第一次来的用户一样点遍预览环境里的每个流程
- 一个人设没耐心，一个人设很困惑，一个人设在用手机
- playwright + chrome devtools mcp 做回归测试

bug

- sentry mcp 捕获报错
- agent 读堆栈，10 分钟内开出修复 pr
- 人只需要点批准

数据

- 每天早上 7 点 posthog mcp 定时分析昨天的漏斗
- 任何一步流失超过 10%，agent 就去看 20 段会话回放并告诉我原因
- 每周一 stripe mcp 把所有取消订阅原因汇总到一份文档

agent 的工具

- orgo，让每个 agent 都有自己的电脑
- agentmail，让每个 agent 都有自己的邮箱
- agentphone，让我开车时也能给它们打电话
- composio connect-apps 搞定其他所有连接器
- akitaonrails/ai-memory，一个基于 git 的 markdown wiki，让它们记得我们上周定了什么

skills

- wshobson/agents，让 skills 在 claude code、codex 和 opencode 之间通用
- 我的写作风格
- 我们的设计系统
- 我们写 spec 的方式
- skill creator，让 agent 自己写新 skill

一些好用的技巧

- 一个平台一个 agent。负责 x 的 agent 从不碰邮件
- 分诊用便宜模型，要上线的东西一律用 opus
- 每个产出都由 llm 评委打 1-10 分，低于 8 分打回
- 每个 agent 每晚写 5 行日志，我 2 分钟就能读完整个公司
- agent 犯的每个错都变成一个新 skill，所以同样的错只犯一次

团队

- 人类拿到的是第 5 版，而不是我的语音备忘，他们对此很开心 lol
- 他们的工作是给创意反馈、维护关系，以及告诉 agent 哪里做错了

人类 pm 每周看一次漏斗，而这套东西每天早上都看

经营公司现在就是语音备忘加推理
