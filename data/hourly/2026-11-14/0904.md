- @gregisenberg [Making the most AI pilled company is the](https://x.com/gregisenberg/status/2121331227009364340) · 浏览 42421 · 每小时 +5633 · 已推送
  - 中文：打造一家最 AI pilled 的公司，就是整场游戏的全部：
    
    1. 做一个第二大脑。用一个文件夹里的 markdown 文件，记下你如何思考、写作和做决策（obsidian）
    
    2. 跟它说话。整天用语音笔记（wispr），再让一个 agent 把每条事实、故事和决策归档
    
    3. 做一个公司大脑。客户、通话、数字、定价、playbook、过往决策以及为什么那样决定
    
    4. 录下每一通通话和每一次会议（granola）。转录直接进入大脑
    
    5. 维护一份 facts 文件。记录关于你和公司的、允许 agents 说出去的真实事项。这能杜绝瞎编的说法
    
    6. 维护一份 voice 文件。你最好的 50 条帖子、你讨厌的 20 条，以及你从不使用的词
    
    7. 把这一切放进 git（github），这样每次改动都有历史
    
    8. 在最顶层写一份指令文件（CLAUDE.md 或 AGENTS.md）。任何任务开始前先读这些文件，永远不要覆盖，始终注明日期
    
    9. 给 agents 跨会话的记忆，让它们别每次都从零开始（claude-mem, mem0）
    
    10. 把所有数据源导入一个仓库，让你的 agents 可以查询（airbyte → clickhouse）。广告、分析、CRM、支付
    
    11. 喂给它别人没有的数据。这是竞争对手唯一下载不走的部分
    
    the skills
    
    12. 不要从零开始。先装好那些优秀的 skills（anthropics/skills, obra/superpowers, mattpocock/skills, addyosmani/agent-skills）
    
    13. 营销相关的也要拿上（coreyhaines31/marketingskills、cody schneider 做静态广告和 UGC 的 graphed skills、boringmarketing dot com 的 skills）
    
    14. 把公司里的每条工作流都画出来，并按能赚到或省下的钱排序
    
    15. 每条工作流亲自做一遍，一边大声讲出来，一边录下来
    
    16. 让一个 agent 把录音变成 skill：什么时候用、步骤、检查项、要避开的错误
    
    17. 一个岗位一个 skill。又小又无聊的，胜过一个巨型 prompt
    
    18. 用 MCP 把工具接上，让 agents 不只是给建议，还能动手（gmail, slack, stripe, linear, notion, posthog, supabase）
    
    19. 给 agents 一个浏览器（browser-use, vercel agent-browser, claude in chrome）
    
    20. 给 agents 一台它们自己的电脑，用来对付没有 API 的工具（vercel agent-desktop, orgo）
    
    21. 把你最好的 skills 公开发出去。这就是新的获客磁铁（lead magnet）
    
    the agents
    
    22. 跑一个永不关闭的编排器（grok bot, openclaw, hermes）。它为每个项目管一个 agent，而这些 agent 再跑自己的 sub-agents
    
    23. 用 coding agents 来做开发（claude code, codex, cursor, t3, antigravity）
    
    24. 给它们套上 harness，让它们会规划、测试和记忆（ECC, superpowers）
    
    25. 在一个地方管理整支舰队（paperclip）。每个 agent 都有任务、预算和日志
    
    26. 把 skills 挂到触发器上（n8n, scheduled tasks）。每天、每周、每有新线索、每次取消时触发
    
    27. 路由你的模型（openrouter）。贵的模型负责规划和检查（fable 5.2, gemini 4 carbon），便宜的模型扛量
    
    28. 砍 token 账单。输出更短，工具返回结果更小（caveman）
    
    29. 对不能离开你机器的数据，跑本地模型（gemma 4）
    
    30. 跟踪每个任务的成本。如果一个任务成本高于它带来的收益，就修好它，或者干掉它
    
    the factory
    
    31. 把流水线搭起来。spec agent → 并行的 builder agents（git worktrees）→ test agent → reviewer agent → 部署（vercel, railway）
    
    32. 设计也走同一条流水线（paper MCP），再用一个 skill 去掉任何看起来像 AI 做的东西（unslop）
    
    33. 公司里每一件烦人的任务，当天结束前都变成一个内部工具
    
    34. 每个客户请求在人类读到之前，先变成一个 pull request（用 tstack 做 PR 工作流）
    
    35. reviewer agents 要有明确的标准：「世界上最强的团队会发这个吗？」答案是 yes 之前就一直拒
    
    36. 保留 50 个有正确答案的真实案例。每次有新模型发布就重跑一遍，然后切到赢家
    
    37. 人类负责批准、对结果负责，以及和客户交谈。这就是你留下的那 10%
    
    the loop
    
    38. 每个完成的任务都写回大脑。什么有效、什么失败、什么该停掉
    
    39. 支持工单、分析和社交评论每天晚上流入
    
    40. 每周五，一个 agent 根据本周结果重写 playbook，你来批准 diff
    
    41. 每个月按「每人力小时利润」给所有事情排序。砍掉一件，加倍一件
    
    the growth
    
    42. 花每一块钱之前，先用 agents 做研究（perplexity API, last30days skill）
    
    43. 外呼自己跑。找线索、enrich、验证、发送（apollo, million verifier, instantly, phantombuster）
    
    44. 给潜在客户的不是推销词，而是已经做完的作品
    
    45. 广告按循环跑。一个 agent 写创意，通过 facebook ads API 发布，干掉失败者，放量赢家
    
    46. 创意也由 agents 来做。图片（nano banana），视频（heygen, fal），语音（elevenlabs），音乐（lyria 3.5, suno）
    
    47. 把每一个完成的任务变成内容。故事、数字、prompt
    
    48. 每个客户都会让大脑对下一个客户更聪明。这就是你的网络效应
    
    49. 一旦跑通，就指向一个新的细分领域。同样的 agents，新的上下文
    
    模型对所有人都一样，但你的上下文是唯一属于你的部分。
    
    尽量多、尽量快地获取它。
    
    像这样去构建循环。
    
    这就是整场游戏，玩得开心。
